# cowork-skill — the canon packaged for Microsoft 365 Copilot Cowork

`roberdan/` is the skill package for **M365 Copilot Cowork** (the Cowork tab of the Microsoft
365 Copilot app) — not GitHub Copilot. Different surface, different shape: Cowork works on
documents, mail, meetings and Teams, with no git, no CI and no terminal, so the engineering
evidence forms (commit SHA, PR, green CI) are replaced by the ones that exist there — the
artifact re-opened and checked, the number traced to its source, the tool failure reported as
a failure rather than as an empty result.

It carries the half the other exports can't: **how to use the tenant**. Gather from WorkIQ /
Teams / Outlook / meetings / OneDrive before answering, because the named failure mode here is
answering from general knowledge when the answer was in his own data; produce real
Word/Excel/deck artifacts instead of chat text; name the source of every figure.

## One skill, not two — and why

Roberto already ran a `Roberdan` twin skill in Cowork, strong on voice (few-shot examples, real
people, `profile.md`, composition with `fde-playbook`). This export used to be a second,
separate skill about method. **Merged on 2026-08-21, his call**, for one mechanical reason:
Cowork loads the skill whose description matches the request. Two skills means a drafting task
loads the voice one and never gets the verification layer, while an analysis task loads the
method one and writes in a generic voice — and there is no way from here to verify the runtime
loads both. So the voice half and the method half live in the same skill and always travel
together.

## What's committed here, and what is not

- **Committed**: `SKILL.md` (core), `VALUES.md` (values + 8 articles + Agentic Manifesto),
  `THINKING.md` (first principles, framework repertoire, bias checks), `ADVISORS.md` (the
  agent set as hats + the board's lenses and its mandatory red team).
- **Never committed, local only**: `profile.md` (portfolio, real people, calendar policies)
  and the worked few-shot examples with real names and threads. The committed `SKILL.md`
  carries the *shape* of those examples, not the people. This repo is public — the split is
  the same one that keeps `private/` out of git.

Hand-derived from `behavior/roberto-mode.md`, `identity/voice.md`,
`behavior/thinking-toolkit.md`, `rules/constitution.md` and the human gates in `AGENTS.md`.
**Not generated by `bin/sync.sh`** — re-derive by hand if the canon changes meaningfully.

## Install

**A — OneDrive folder (auto-detected).** Put the whole folder at:

```
OneDrive/Documents/Cowork/Skills/roberdan/
    SKILL.md  VALUES.md  THINKING.md  ADVISORS.md   +  profile.md (local only)
```

Cowork picks up every skill under `Documents/Cowork/Skills/<name>/`. No admin needed.

**B — Upload from the app.** Cowork → **Personalizza** → **Skill** → *Aggiungi / Carica* →
select `SKILL.md`, or a zip of the whole folder so the companion files travel with it.

The skill then loads by itself when a request matches its `description`, and shows up under
**Competenze e plug-in** in the right-hand workspace panel — that panel is the check that it's
actually active.

**Frontmatter is parsed, not skimmed.** A `description` containing `: ` is not a valid YAML
scalar and Cowork rejects the upload with *"manca la descrizione"* even though the line is
right there. `test/test-frontmatter.sh` now parses every exported `SKILL.md` the way a loader
would; keep name and description quoted.
