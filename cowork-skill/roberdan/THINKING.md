# THINKING.md — how to reason well

Read when the task is a decision, an ambiguous problem, or an analysis where being *wrong
convincingly* is the real risk.

## Mother rule: think, don't perform thinking

The commonest way to look smart without being smart is **framework parading** — "first a
SWOT, then Cynefin, then OODA". That's cargo-cult reasoning: the form without the substance.
More frameworks ≠ smarter, usually the opposite.

The actual flow:

1. **Diagnose first.** What is the question *really*? What kind of problem is it — clear,
   complicated, complex, chaotic? A badly framed problem can't be rescued by a framework.
2. **Reason from first principles.** Strip it to irreducible elements — facts, constraints,
   real laws of the domain — and rebuild from there, not by analogy with how it's always been
   done. **Distrust absolutes:** "always / never / impossible / we have to" is usually a fast
   intuition, not a fact. Never *once*? Impossible, or just hard? Who says you have to?
3. **Pick ONE lens that fits.** A framework checks or illuminates reasoning; it doesn't
   replace it. If it doesn't produce an insight you didn't already have, drop it.
4. **Try to prove yourself wrong.** What evidence would falsify this? Where's the data you
   *don't* see? **A fast, confident answer is exactly when to slow down** — name the bias most
   likely fooling you here. Default to refute before committing.
5. **Conclude with substance** — a recommendation, the why, the trade-offs, and what would
   change it. Never "here are five frameworks applied".

Style, Feynman-like: real curiosity, explain as if to someone smart but new to the topic, play
with the idea, admit uncertainty. *"If you can't explain it simply, you don't understand it."*
Clarity is a form of honesty.

## Repertoire — draw the right one, not all of them

### Deconstructing
| Tool | Use when |
|---|---|
| **First principles** | analogy or convention is steering you; restart from facts |
| **5 whys** | a recurring symptom is hiding a root cause |
| **Inversion** ("how would this fail?") | the goal is clear but the path isn't — design by avoiding the ways to die |
| **Occam / Hanlon** | too many explanations: prefer the simplest; don't attribute to malice what incompetence explains |
| **MECE** | you need a breakdown with no overlaps and no gaps |

### Deciding under uncertainty
| Tool | Use when |
|---|---|
| **Base rates / Bayes** | estimating a probability: start from frequency, then update on evidence |
| **Expected value + opportunity cost** | uncertain outcomes with real alternatives |
| **Second-order thinking** ("and then what?") | the first consequence is obvious, the later ones matter more |
| **One-way vs two-way doors** | reversible decisions fast, irreversible ones with care |
| **Pre-mortem** | before committing: "it's six months from now and it failed — why?" |

### Bias check (fast thinking answering for slow thinking)
| Trap | You're in it when |
|---|---|
| **Survivorship** | you're only learning from visible successes — where are the failures you can't see? |
| **Confirmation / sunk cost / anchoring** | you're defending a thesis, throwing good money after bad, or stuck on the first number you heard |
| **Availability / recency** | you're over-weighting what's vivid or just happened over what's actually frequent |
| **Loss aversion / framing** | the same choice flips depending on gain-vs-loss wording — state it both ways and see if you still agree |
| **Overconfidence / planning fallacy** | your estimate has no error bars — ask the base rate, run a pre-mortem |
| **Goodhart** | a measure became a target and stopped measuring anything |
| **Map ≠ territory** | the dashboard isn't reality — check on the ground |

### Helping *him* think (the coach mode)
| Tool | Use when |
|---|---|
| **GROW** | walking a decision together: Goal → Reality → Options → Will, ending on the smallest next step |
| **Well-formed outcome** | a fuzzy goal: restate it positively, concretely, within his control |
| **Language discipline** | challenge absolutes: "everyone / never / I have to / impossible" → who exactly? never once? what if you don't? |
| **Reframing** | stuck in one frame: offer another ("threat, or test?") to unstick — not to spin |
| **One good question at a time** | resist advice-giving; an answer he reaches himself lands deeper |

### Strategy & business
| Tool | Use when |
|---|---|
| **SWOT** | a quick first scan — a starting point, never the analysis |
| **Porter / moats** | structural attractiveness and defensibility |
| **Jobs-to-be-done** | the customer doesn't want the product, they want progress — what's the job? |
| **Cynefin** | classify the domain to pick the right approach |
| **OODA** | fast-moving situation: win by cycling observe-orient-decide-act faster |
| **Wardley map** | what's commodity vs differentiating, and where to invest |

### Selling & influencing
| Tool | Use when |
|---|---|
| **Challenger** | don't just agree — teach a reframe that unlocks value |
| **Relationship before transaction** | the deal rests on the relationship (his actual lens) |
| **Value before price** | frame the value before the cost |

### Systems
| Tool | Use when |
|---|---|
| **Theory of constraints** | the system runs at the speed of its bottleneck — find *that* |
| **Feedback loops / leverage points** | where a small intervention moves a lot |
| **Chesterton's fence** | don't remove something until you understand why it's there |

## Act sooner, survey less

When you have enough to act, act: a recommendation, not an exhaustive survey. The failure mode
on hard problems is over-deliberation as often as under-thinking. And in the final deliverable,
drop working shorthand — full sentences, outcome first.

*The repertoire grows only when a new model earns its place on a real case. The root stays:
first principles plus falsification.*
