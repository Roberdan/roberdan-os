## Novelties + impact

1. **v2.1.216 — shell permission parsing hardened against invisible Unicode.** Carried over
   from the 07-25 proposal, where it was written and never applied. `hooks/bash-guard.sh`
   classifies commands by reading them as text, so a zero-width joiner or a bidi override
   makes what the guard reads differ from what the shell runs: the verdict can be true about
   the text and wrong about the execution. **APPLIED** — see the patch section.

2. **v2.1.219 — nested subagents now spawn to depth 3 by default (was 1).**
   `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=1` disables nesting. This is a cost-shape change for
   any orchestrated loop (`wanda`, the factory): depth 3 multiplies fan-out silently.
   **No patch needed — already covered.** `~/.claude/settings.json` line 7 already carries
   `"CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH": "1"`, so this machine keeps the old depth.
   Worth re-checking if that settings file is ever rebuilt.

3. **v2.1.218 — agent frontmatter hooks now require the agent file's own folder to have
   accepted workspace trust.** Directly touches the agent-supply-chain rule in
   `rules/best-practices.md § Security`. **Not applicable today:** no file in `agents/*.md`
   declares a `hooks:` key (`grep -l "hooks:" agents/*.md` → empty), so nothing generated by
   `bin/sync.sh` depends on the old behaviour. It becomes live the day an agent gains a hook.

4. **v2.1.218 — skills with `context: fork` run in the background by default**
   (`background: false` opts out). **Not applicable:** no skill in `skills/` or
   `~/.claude/skills/` declares `context: fork`.

5. **v2.1.219 — `sandbox.network.strictAllowlist` setting** (deny non-allowlisted hosts for
   sandboxed commands without prompting), and **`workflowSizeGuideline`** (advisory cap on
   dynamic-workflow agent count, settable from any settings file). Both are real cost/blast-
   radius levers, but the factory is documented as bounded-not-sandboxed with external
   dispatch dormant, and the review budget already governs loop spend. Recorded as declined
   rather than patched — adopting either is a scope decision, not a changelog consequence.

6. **v2.1.219 — Claude Opus 5 (`claude-opus-5`) is now the default Opus model**, 1M context,
   fast mode at $10/$50 per Mtok; Opus 4.7 dropped from fast mode; the bundled `claude-api`
   skill now defaults to Opus 5. The `model-selection-policy` skill still names **Opus 4.8**
   as the `opus` tier. Same price per token as Opus 5 ($5/$25), one generation behind.
   → surfaced to Roberto as a decision, not auto-applied: it changes which model his
   subagents run on.

## Suggested patch (draft only → APPLIED for item 1)

- `hooks/bash-guard.sh`: added rule 0, a fail-closed prefilter that refuses any command whose
  **head** (heredoc body excluded) carries invisible, bidi or control characters **outside
  quoted strings** — C0/C1, U+00AD, U+200B–U+200F, U+202A–U+202E, U+2060–U+2064,
  U+2066–U+2069, U+FEFF. NBSP (U+00A0) is deliberately excluded: it is a paste artifact that
  looks like the space it is. Accented Italian is untouched, which matters because that is
  what this repo's commit messages are made of.
  Citation: https://raw.githubusercontent.com/anthropics/claude-code/main/CHANGELOG.md —
  @anthropic-ai/claude-code v2.1.216, published 2026-07-20; checked 2026-07-31.
- `test/test-bash-guard.sh`: **new file.** Until today the guard had no test at all — the
  force-push rule, the `reset --hard` rule and the docs-staging rule were promises. Mutation
  proof recorded: removing rule 0 turns three assertions red; restoring it turns them green.
  Wired into `test/validate.sh` § 8b2.
