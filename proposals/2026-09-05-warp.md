## Novelties + impact

### 1. 2026.09.09 — "Claude Code and Codex runs can now access Factory MCP automatically" (Oz, #15827)

**Evidence.** Oz updates, 2026.09.09. It extends the built-in Factory MCP server (2026.08.18, assessed
in `proposals/2026-08-29-warp.md` § 1) from Warp's own agent to **Claude Code runs launched through Oz**,
attached automatically.

**Impact.** This is the shape `rules/best-practices.md` § Security & Privacy forbids: an MCP server that
reaches a Claude Code session without a review, in a session that can read `private/`. Today roberdan-os
does not launch Claude Code through Oz — `factory/engine.sh` `launch_agent` runs `copilot -p` (default) or
`claude -p` directly under launchd — and `~/.claude.json` lists only `gbrain` and `roberdan-bus`
(checked 2026-09-14). Warp.app and `oz` are installed on this machine, so the exposure is one habit away:
starting Claude Code from an Oz run instead of a plain terminal.

**Suggested patch, awaiting Roberto.** No canon change. One advisory check in `bin/doctor.sh`: when `oz`
is on PATH, warn if a Claude Code session started under Warp reports a Factory MCP server in its tool
list, pointing at the Security & Privacy rule. Alternative with zero code: Roberto disables Factory MCP
in Warp settings on this machine (machine action, not a repo patch).
