## Novelties + impact

### 1. 2026-08-12 / 2026-08-13 — Agent Plugins 1.0 is generally available in Copilot CLI

**Evidence.** The GitHub Changelog entry **"Agent Plugins 1.0 in VS Code, Copilot CLI, and the Copilot app"** was published **2026-08-12T18:39:11Z**. It says Agent Plugins 1.0 packages skills and MCP servers into one installable plugin, is GA in VS Code, Copilot CLI, the Copilot SDK and app, and uses a `plugin.json` manifest with `skills/`, `mcp.json`, plus Copilot-specific files under `com.github.copilot/`. The weekly release entry published **2026-08-14T03:15:56Z** also lists Agent Plugins 1.0 as generally available. GitHub Docs says plugins can contain custom agents, skills, hooks, MCP and LSP configs, and Copilot CLI can install them with `copilot plugin install` or `/plugin install`.

**Impact on roberdan-os.** This is the first Copilot change in this window that materially overlaps roberdan-os: `bin/sync.sh --install` currently generates user-scoped Copilot agents, prompts and a user-scoped extension directly under `~/.copilot`. Agent Plugins would let roberdan-os distribute one portable Copilot package instead of several generated locations. That could reduce drift, but it also changes install/update governance and introduces plugin marketplace trust.

**Suggested patch, awaiting Roberto.** Add a new, opt-in `bin/sync.sh --emit-copilot-plugin` path, or a sibling helper such as `bin/copilot-plugin.sh`, that emits a draft plugin directory under gitignored `platforms/copilot-plugin/`:

- `plugin.json` with the Agent Plugins 1.0 schema.
- `skills/` from roberdan-os skills.
- `agents/` or Copilot-specific custom agents under `com.github.copilot/`, depending on the final schema requirement.
- `hooks.json` and/or extension files only if the Copilot CLI docs confirm the exact package shape.

Do not replace the current installer yet. This is a behavior/distribution change and needs Roberto approval plus tests that prove the generated plugin is deterministic and does not widen tool access.

### 2. Copilot CLI 1.0.81-6 — `/tasks`, `/plugin`, `/rewind`, `/memory`, `/remote`, `/fleet`, `/autopilot`

**Evidence.** The local Copilot CLI help for **1.0.81-6** lists `/tasks` for subagents and shell commands, `/plugin` for plugin marketplaces, `/rewind` to restore Copilot changes without requiring git or discarding user edits, `/memory` for cross-session memory, `/remote`, `/fleet`, and `/autopilot`. The 2026-08-13 weekly GitHub Changelog entry says Copilot CLI can manage all subagents and tasks in `/tasks`, queue prompts/shell/slash commands while a turn runs, combine `--plan` and `--mode autopilot` in headless mode, use `/rewind`, and preserve context when opening `/app`.

**Impact on roberdan-os.** `/tasks` overlaps with `kb` only superficially: `kb` is still the durable, gated ledger. `/rewind` is useful because roberdan-os forbids destructive cleanup and force-reset shortcuts, but making it a canonical recovery command changes operator behavior. `/memory` conflicts with `memory/memory-protocol.md`, which explicitly says not to use host-native memory silos; the Copilot helper list confirms the feature exists, but canon should keep rejecting it unless Roberto changes the memory strategy.

**Suggested patch, awaiting Roberto.** Consider a small `docs/USAGE.md` section "Copilot CLI recovery and native task surfaces":

- Prefer `/rewind` over `git reset --hard` for undoing the last Copilot turn when no commit exists.
- Treat `/tasks` as a runtime panel only; `kb` remains the source of truth.
- Keep `/memory` disabled/unused for roberdan-os memory; use vault + gbrain instead.

Not applied automatically because it changes the documented operator playbook.
