## Novelties + impact

### 1. 2026.08.18 / 2026.08.27 — Warp Factories in Early Access, and a built-in Factory MCP server for logged-in users

**Evidence.** 2026.08.18: "Warp Factories is now live in Early Access" and "**Warp now includes a
built-in Factory MCP server for logged-in users.**" Repeated at 2026.08.19, 2026.08.25 and 2026.08.27,
which links the launch post <https://www.warp.dev/blog/open-infrastructure-for-building-a-software-factory>.

**Impact on roberdan-os — naming collision first, adoption question second.**

*Naming.* `factory/factory-protocol.md:1-6` defines roberdan-os's own "factory": queued tasks through
headless `claude -p` agents on a durable file queue + `launchd`. That name is now also a Warp product.
Anyone reading a future note saying "the factory failed overnight" has two referents. This is the only
part of the item with a concrete, cheap patch.

*Adoption.* Not recommended, and the reasons are already in the canon rather than new:
`rules/best-practices.md` § *Security & Privacy* — "no third-party skill/MCP server enters the stack
without a review of its SKILL.md + bundled scripts", and "a session that can read `private/` never gets
an unreviewed MCP server attached". A **built-in** MCP server enabled for logged-in users is exactly the
shape that rule exists for: it arrives with a client update rather than through a review. The prior
decline of Warp Cloud Runners ("no reviewed cloud-runner isolation contract", 2026-07-28) applies
unchanged to Factories' cloud execution.

*Surface check.* Warp has no adapter in this repo: `ls platforms/` → `chatgpt claude codex copilot hermes`
(no `warp`), and the only executable reference is `bin/doctor.sh:136`, which merely checks whether a
`warp` binary exists. Nothing generated by `bin/sync.sh` would be affected by adopting or ignoring
Factories.

**Suggested patch, awaiting Roberto.** Documentation only — one disambiguating line in
`factory/factory-protocol.md`, immediately under the title:

```diff
 Runs queued tasks through **headless Claude Code agents**, one after another, unattended and
 resumable — the "agent factory" that keeps going while you sleep.
+
+> Unrelated to **Warp Factories** (Early Access since Warp 2026.08.18), which is Warp's own
+> cloud build infrastructure plus a built-in Factory MCP server. Not adopted: an MCP server that
+> arrives enabled with a client update does not pass the review gate in
+> `rules/best-practices.md` § Security & Privacy.
```

And, if Roberto wants a mechanical consequence rather than a note: check whether Warp's built-in Factory
MCP server appears in a Warp session's MCP list on this machine, and if so disable it there. That is a
machine action, not a repo patch. Citation: warp changelog 2026.08.18 and 2026.08.27.

### 2. 2026.08.18 — `oz agent run-cloud` accepts `--title` and `--parent-run-id`

**Evidence.** 2026.08.18: "`oz agent run-cloud` now accepts `--title` and `--parent-run-id`, so
third-party harnesses can set a run's title and orchestration lineage."

**Impact on roberdan-os.** This is the concrete form of what was declined on 2026-08-21 as
"repository-qualified child-agent skill references … useful only for a future Warp adapter". Same
conclusion, now with the flags named: lineage would matter if roberdan-os ever dispatched work into
Warp cloud runs, and it does not — the factory dispatches `claude -p` locally under launchd
(`factory/factory-protocol.md:18-19`). **No patch.** Re-declined with the flag names recorded, so a
future Warp adapter starts from a fact instead of a re-read.

### 3. 2026.08.27 — Ctrl-C in an attached third-party harness session (e.g. Claude Code) now resolves to cancelled

**Evidence.** 2026.08.27: "Pressing Ctrl-C in an attached third-party agent harness session (e.g. Claude
Code) now correctly resolves it to cancelled instead of leaving it stuck showing in progress"
([#15506](https://github.com/warpdotdev/warp/pull/15506)). Alongside it: cloud agent runs now always
report a terminal status on process exit ([#15387](https://github.com/warpdotdev/warp/pull/15387)).

**Impact on roberdan-os.** Relevant only to the ergonomics of running Claude Code inside Warp, which is
how Roberto interactively works. It removes a stale "in progress" that the `long-running-jobs` skill's
terminal-condition discipline exists to survive. Warp-side fix, no repo change. **No patch.**
