## Novelties + impact

### 1. 2026.08.07 — `SKILLS_DIRS` indexes extra skill directories in agent-driver mode

**Evidence.** Warp **2026.08.07 (v0.2026.08.05.09.03)** says: "Support `SKILLS_DIRS` env var in agent-driver mode to index extra skill directories at personal-skill precedence" (#14394).

**Impact on roberdan-os.** This is the only Warp change in the new window that touches roberdan-os's skill distribution model. The repo currently has `skills/` as canonical markdown and `bin/sync.sh` emits per-client wrappers. Warp's `SKILLS_DIRS` could let a Warp agent index roberdan-os skills directly, but "personal-skill precedence" is the risky part: it can shadow project-local skills unless namespacing and collision rules are understood.

**Suggested patch, awaiting Roberto.** Add a Warp-specific section to `docs/USAGE.md` after Roberto approves the behavior:

- Export `SKILLS_DIRS=/Users/Roberdan/GitHub/roberdan-os/skills` only for a Warp agent-driver session that is intentionally operating under roberdan-os.
- Do not set it globally until a collision test proves Warp's precedence will not shadow a project skill unexpectedly.
- If collisions occur, prefer the same `rdos-<name>` namespacing policy already used for Copilot/Claude skill collisions.

Not applied automatically because it changes how Warp discovers skills and could alter behavior in every Warp session.

### 2. 2026.08.13 — child agents can launch with repository-qualified skill references

**Evidence.** Warp **2026.08.13 (v0.2026.08.12.21.54)** says child agents can be launched with repository-qualified skill references instead of absolute paths (#14271).

**Impact on roberdan-os.** This might eventually be a cleaner way to point Warp child agents at roberdan-os skills without baking absolute paths. The current repo has no Warp launcher that emits child-agent skill references, so there is no direct patch today.

**Suggested patch.** None now. If a Warp adapter is added later, prefer repository-qualified references over absolute paths and test that they resolve only inside the intended repo.

### 3. 2026.08.13 — Warp Agent CLI multi-level orchestration is visible in the Agents bar

**Evidence.** Warp **2026.08.13** says the Warp Agent CLI Agents bar mirrors GUI multi-level orchestration, with drill-down, breadcrumbs, and subtree rollup badges (#14884).

**Impact on roberdan-os.** roberdan-os deliberately treats nested orchestration as a cost and control risk. Visibility is useful, but it does not replace the repo's review-budget and human-gate rules.

**Suggested patch.** None. Continue to keep orchestration policy in `loop/loop-protocol.md` and `factory/factory-protocol.md`.

### 4. 2026.08.13 — inactive toolbelts and canceled background commands fixed

**Evidence.** Warp **2026.08.13** fixes inactive agent toolbelts continuing to run hidden context-chip commands (#14854) and canceled background commands leaving wrapped child processes running (#14853). It also fixes background orchestrated agents stealing focus (#14829/#14961) and long-running commands not accepting keyboard input (#14943).

**Impact on roberdan-os.** These fix Warp-side operational safety issues around background agents and command lifecycle. roberdan-os should not loosen its own constraints because a terminal fixed its UI/process handling. No repo behavior depends on these bugs being present or absent.

**Suggested patch.** None.

### 5. 2026.08.13 — excessive Git process creation when loading global skills fixed

**Evidence.** Warp **2026.08.13** fixes excessive Git process creation when loading global skills (#14830).

**Impact on roberdan-os.** This makes a future `SKILLS_DIRS`-style direct skill load less risky from a performance standpoint, but it is not enough to approve global direct loading by itself.

**Suggested patch.** None until Roberto chooses a Warp skill-loading strategy.
