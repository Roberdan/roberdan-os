## Novelties + impact

### 1. Copilot CLI v1.0.84-4 — breaking restructure of `copilot plugins` (checked first: not affected)

**Evidence.** v1.0.84-4 **Removed**: `copilot plugins install --skill` → `copilot skill add`; cross-kind
`--kind/--scope/--mcp/--skill` flags gone; `copilot plugins list --json` now a flat array.

**Impact.** The only breaking item in the window, so verified by grep rather than assumed:
`grep -rn "copilot plugins\|copilot plugin \|plugins list\|--kind \(instruction\|lsp\|skill\|mcp\)"`
over the repo (proposals/ excluded) returns nothing. `bin/sync.sh` installs Copilot skills and agents as
symlinks under `~/.copilot/` and only *reads* `mcp-config.json` (`bin/sync.sh:585-587`). **No patch.**

### 2. Copilot CLI v1.0.83-2 — custom agents can list several models; `model-policy: required`

**Evidence.** v1.0.83-2 (stable in v1.0.83, 2026-09-04): "Custom agents can list several models in `model`,
tried in order until one is available to you, and `model-policy: required` keeps model changes on that
list".

**Impact.** Reopens, with something materially new, the 2026-08-01 decline: *if an admin policy removed
`claude-opus-5`, our Copilot agents would degrade silently*. `bin/sync.sh:332-334` writes one
registry-resolved id per agent (`platforms/copilot/agents/socrates.md:5` → `model: claude-opus-5`) and no
`model-policy`. With `model-policy: required` the reviewed id becomes a constraint instead of a preference.
A multi-model list is **not** proposed: falling back to an older generation is what
`rules/best-practices.md` § Subagent models forbids.

**Suggested patch, awaiting Roberto — test first.** In the Copilot agent generator (`bin/sync.sh`, near
line 334) emit `model-policy: required` under the resolved `model:`. Before adopting, verify in one
session what Copilot does when the single listed model is unavailable — a loud error is the wanted
outcome; if it silently picks another model, drop the patch. Pin it in `test/test-copilot-adapter.sh`.

### 3. Model retirements with a date + Claude Fable 5.1 in Copilot — registry refresh

**Evidence.** Retiring **2026-10-02**: Claude Opus 4.7, Gemini 3.5 Flash, Gemini 3.6 Flash, Kimi K2.7 Code.
Retired **2026-09-10**: MAI-Code-1-Flash. Claude Fable 5.1 available to Pro+/Max/Business/Enterprise

(`bin/lib-models.sh:100`); nothing else in the repo names them. `claude-fable-5.1` and `kimi-k2.7-code`
sit in the deferred comment. Nothing breaks on 10-02; the rows just become false.

**Suggested patch.** At the next registry review (`copilot help config` on the installed CLI): remove the
four retired rows and their names from `test/test-model-registry.sh:91-92`, and add a reviewed

deferred, per the file's own rule.
