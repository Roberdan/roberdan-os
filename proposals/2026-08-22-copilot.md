## Novelties + impact

### 1. 2026-08-26 — Global model policy GA: Fable 5 disabled by default on Business/Enterprise

**Evidence.** The changelog entry "Global model policy generally available" (2026-08-26T22:08:38Z) says GitHub is gradually rolling out enforcement of the default model policy through September 1, 2026, for Copilot Business and Copilot Enterprise plans. The key clause: _"We exclude open-weight models (e.g., DeepSeek and Kimi K2) and models not covered by GitHub's data retention agreement (e.g., Fable 5) from default enablement, regardless of your policy."_ Unconfigured models previously set to no explicit state will inherit the global policy; Fable 5 is explicitly named as one that requires an administrator to explicitly enable it.

**Impact on roberdan-os.** Two angles:

1. **Generated Copilot agents** (`bin/sync.sh`, `copilot_model()`): the function maps only `opus→claude-opus-5`, `sonnet→claude-sonnet-5`, `haiku→claude-haiku-4.5`. No generated agent frontmatter pins `fable-5` or any Fable variant. Verified by grep on the worktree — no Copilot model ID referencing Fable 5 exists in generated output. **No automated impact.**

2. **Interactive Copilot CLI use.** The global instructions explicitly name Fable 5 as the default main-session model (`/model`). If Roberto's Copilot account is on a Business or Enterprise plan, Fable 5 will be unavailable interactively in Copilot CLI after September 1 unless an administrator explicitly enables it under model settings. The changelog confirms the policy enforces at the organization/enterprise level and does not affect personal plans (Pro, Pro+, Max). If on a personal plan: no action needed. If on a Business/Enterprise plan: an admin must go to Copilot settings → Models → Fable 5 → explicitly enable it before September 1.

**Suggested patch, awaiting Roberto.** Add a one-liner to `docs/USAGE.md` under the existing Copilot model-verification section (line 87 area, which already says factory clamps "fable" → "sonnet"):

```markdown
## Copilot CLI — Fable 5 and the global model policy

If your Copilot account is on a Business or Enterprise plan: Fable 5 is excluded
from default enablement as of September 1, 2026 (global model policy GA, 2026-08-26).
Interactive `copilot -p … --model fable-5` will return a policy error unless an admin
explicitly enables it in Settings → Copilot → Models. Personal plans (Pro, Pro+, Max) are
unaffected. Generated roberdan-os agents do not pin Fable 5 (sync.sh maps only opus/sonnet/haiku).
```

Not applied: behavior decision, Roberto's gate. The pre-existing `test/test-copilot-adapter.sh` model-ID verification discipline (established 2026-07-31) covers the generated-agent side; the USAGE note covers the interactive side.

### 2. 2026-08-27 — Copilot code review: expanded to bot PRs, large PRs, and resolution reasons

**Evidence.** Entry "Copilot code review: Resolution reasons and expanded capabilities" (2026-08-27T22:46:04Z): Copilot code review can now review PRs authored by bots (including Copilot cloud agent) and PRs exceeding the previous 300-file / 20,000-line limit. A new dropdown allows specifying resolution reasons ("Addressed", "Won't fix", "Incorrect") on review comments.

**Impact on roberdan-os.** roberdan-os routes code review through `@rex` (local, canon-gated) and `@thor` (done-gate). Copilot's cloud review agent is not wired into the roberdan-os review loop (`evolve-protocol.md` and `AGENTS.md` both keep the gate here). No patch required.

**Suggested patch.** None.

### 3. 2026-08-26 — Enterprise-managed settings: autoUpdate for plugin marketplaces

**Evidence.** Entry "Enterprise-managed settings now support autoUpdate for plugin marketplaces" (2026-08-27T01:52:19Z): `autoUpdate: true` on an `extraKnownMarketplaces` entry makes supported clients (Copilot app, Copilot CLI, VS Code) automatically update plugins from that marketplace, subject to the `strictKnownMarketplaces` allowlist.

**Impact on roberdan-os.** This is governance infrastructure for Agent Plugins, which `proposals/2026-08-08-copilot.md` proposed as a possible future package format for roberdan-os skills. Since that proposal is still awaiting Roberto's decision (no plugin emitted yet), this feature is not yet applicable. If the Agent Plugins path is adopted, an `autoUpdate` decision would be part of that governance design. No canon change now.

**Suggested patch.** None.

### 5. 2026-08-21 — Copilot in Slack (public preview) and in Microsoft Teams (public preview)

**Evidence.** Entries "The new GitHub Copilot experience in Slack" and "Shared agentic work with GitHub Copilot in Microsoft Teams" (both 2026-08-21). Both bring the Copilot cloud agent into chat/collaboration platforms, allowing teams to start agent sessions from channels/DMs and receive async PRs. Both features are public preview; if the Teams/Slack path ever becomes the coordination channel, the gate discipline would need re-assessing at that time.
